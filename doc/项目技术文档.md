## 一、项目定位

FitCoach Server 是 FitCoach AI 健身教练的后端服务，基于 Spring Boot 3.2 构建，**同时承担**：

- **客户端 API**：为 RN 客户端（[FitCoachRN](../../FitCoachRN)）提供登录、用户、动作元信息、会员、支付、反馈、日志上传、版本检查、轮询入口等能力；
- **管理后台 API**：为运营后台（[FitCoachAdminManager](../../FitCoachAdminManager)）提供 `/api/admin/**` 路径下的全部数据管理能力，独立鉴权链路。

按业务领域划分为 10 个 Maven 模块，模块间走单向依赖；公共模块零业务、业务模块零循环依赖。

## 四、HTTP 接口约定（客户端协议）

### 4.1 X-Client-* 六件套 + Bearer Token

每个客户端→server 请求都带：

| Header | 类型 | 例 | 用途 |
|--------|------|----|----|
| `Authorization` | string | `Bearer <jwt>` | 已登录时带 |
| `X-Client-Platform` | string | `android` / `ios` | 区分平台 |
| `X-Client-Native-Version-Code` | int | `1002003` | 安装包版本 |
| `X-Client-Native-Version-Name` | string | `1.2.3` | 同上，可读 |
| `X-Client-Bundle-Version-Code` | int | `1002005` | JS bundle 版本（OTA 后会与 native 不同） |
| `X-Client-Bundle-Version-Name` | string | `1.2.5` | 同上，可读 |
| `X-Device-Id` | string | `<uuid>` / `unknown` | 设备唯一标识 |
| `X-Client-Lang` | string | `zh-CN` / `en` ... | 国际化（i18next.language） |

注册：[`ClientInfoInterceptor`](../fitcoach-common/src/main/java/com/lanprojects/fitcoach/common/client/ClientInfoInterceptor.java) + [`ClientContext`](../fitcoach-common/src/main/java/com/lanprojects/fitcoach/common/client/ClientContext.java) + [`ClientVersionInfo`](../fitcoach-common/src/main/java/com/lanprojects/fitcoach/common/client/ClientVersionInfo.java)，在 [`WebConfig`](../fitcoach-app/src/main/java/com/lanprojects/fitcoach/config/WebConfig.java) 注册 `/api/**`（排除 `/api/admin/**`）。

**编码规则**：`MAJOR*1_000_000 + MINOR*1_000 + PATCH`（每段 0-999）；RN / Kotlin / iOS / Java 算法一致。

### 4.2 业务侧用法

```java
import com.lanprojects.fitcoach.common.client.ClientContext;

// 1) versionCode 条件判断（最常用）
if (ClientContext.bundleVersionCode() >= 1_001_000) { /* 1.1.0+ 走新逻辑 */ }

// 2) 平台分流
if (ClientContext.isIos()) { /* iOS 用 Apple IAP */ }

// 3) deviceId（单设备互踢、风控）
String deviceId = ClientContext.deviceId();
if (ClientContext.get().hasDeviceId()) { /* 真实 UUID，可绑定/比对 */ }

// 4) 全量信息
ClientVersionInfo info = ClientContext.get();
if (info.isEmpty()) { /* admin / Postman / 老版本 */ }
```

### 4.3 缺失语义

- admin / Postman 调试请求 → `ClientContext.get()` 返回 `EMPTY`，`isEmpty()=true`；
- Header 存在但格式异常（version 不是数字）→ 静默降级为 0，不打 ERROR；
- `X-Device-Id` 缺失或为 `unknown` → 用 `hasDeviceId()` 双判，避免把"未知设备"当成"另一台设备"误处理。

## 五、统一返回与错误码

### 5.1 Result 信封

所有 controller 返回 [`Result<T>`](../fitcoach-common/src/main/java/com/lanprojects/fitcoach/common/model/Result.java)：

```json
{ "code": 0, "message": "success", "data": { ... } }
```

业务异常抛 [`BusinessException(ResultCode, message?)`](../fitcoach-common/src/main/java/com/lanprojects/fitcoach/common/exception/BusinessException.java)，由 [`GlobalExceptionHandler`](../fitcoach-common/src/main/java/com/lanprojects/fitcoach/common/exception/GlobalExceptionHandler.java) 统一转 Result。

### 5.2 错误码分段

| 区段 | 含义 |
|------|------|
| `0` | 成功 |
| `1001-1099` | 认证 / Token 异常（含 1006 SESSION_KICKED） |
| `3001-3099` | 用户 / 状态相关（含 3002 USER_DISABLED） |
| `4001-4999` | 业务通用 |
| `7001-7099` | 管理员鉴权（admin 模块） |
| `7101-7199` | 反馈业务 |
| `7201-7299` | 用户管理（admin 端调用） |
| `7301-7399` | 客户端日志拉取 |
| `7501-7599` | 动作 / 会员 / 套餐 |
| `8001-8199` | 支付（含 8001 MEMBERSHIP_REQUIRED） |

### 5.3 全局拦截码（客户端关注）

| code | 含义 | 客户端动作 |
|------|------|-----------|
| `1006` | SESSION_KICKED | logout + toast + 跳 Login |
| `8001` | MEMBERSHIP_REQUIRED | 跳会员中心 |
| `1001-1003` | token 过期 / 无效 | httpClient 自动 refresh + 重放 |

## 七、五大核心机制

### 7.1 单设备登录互踢

> 服务端权威，客户端无脑遵从。

**数据**：`user` 表新增 `current_session_id` / `current_device_id` / `current_login_at`。

**链路**：

```
设备 A 登录 (X-Device-Id=A)
    ↓ AuthService.rotateSessionForLogin
    ↓ if hasDeviceId(): sid_A = UUID()，user.currentSessionId = sid_A
    ↓ JWT claim 加 sid=sid_A 一并签发

设备 B 登录 (X-Device-Id=B)
    ↓ 同上 → user.currentSessionId 翻成 sid_B

设备 A 任意鉴权请求 (jwt.sid=sid_A)
    ↓ AuthService.getCurrentUser → parseAndAssertSession
    ↓ sid_A != user.currentSessionId(=sid_B)
    ↓ throw BusinessException(ResultCode.SESSION_KICKED)  // code=1006

RN httpClient 全局拦截 1006
    ↓ setSessionKickedHandler 注入的回调 (RootNavigator 提供)
    ↓ UserManager.logout() + ToastAndroid + navigationRef.navigate('Login')
```

**关键点**：

- JWT `sid` claim：[`JwtUtils.parsePayload`](../fitcoach-login/src/main/java/com/lanprojects/fitcoach/login/util/JwtUtils.java) 返回 `JwtPayload(uid, sessionId)` record；老 `parseAndVerify` 保留兼容。
- 单点校验：[`AuthService.getCurrentUser`](../fitcoach-login/src/main/java/com/lanprojects/fitcoach/login/service/AuthService.java) → `parseAndAssertSession`；包括通用轮询 `/api/client/poll`。
- refresh 不滚 sid：旧设备拿旧 refreshToken 也会被同处校验拦下。
- 不参与互踢：无 `sid` claim（老 token）/ 无 `X-Device-Id`（admin/Postman）→ 跳过比对。

### 7.2 通用客户端轮询（fitcoach-clientbus）

`GET /api/client/poll` 是客户端"什么都问 server 一次"的统一入口，**替代了原来零散的** `/api/logs/pending` 等专用接口。

**SPI 聚合**：业务模块实现 `ClientPollContribution`，由 [`ClientPollController`](../fitcoach-clientbus/src/main/java/com/lanprojects/fitcoach/clientbus/controller/ClientPollController.java) 在一次 HTTP 中聚合：

| 实现 | 字段 | 含义 |
|------|------|------|
| `LogPullContribution`（fitcoach-log） | `data.logTask` | 待领的日志拉取任务 |
| （未来）`ForceUpdateContribution` | `data.forceUpdate` | 是否需要强更弹窗 |
| （未来）`ServerTimeContribution` | `data.serverTime` | 时间校对 |

响应：

```json
{ "code": 0, "data": { "logTask": { ... }, "serverTime": 1717000000000 } }
```

未命中字段就不出现。客户端用 `data.logTask ?? null` 处理。

**鉴权**：复用 `AuthService.getCurrentUser`，因此天然带上 1006 SESSION_KICKED 能力 —— 无操作的用户也会在下个 120s tick 被踢。

### 7.3 配置热更新（SysConfig）

| 设计 | 说明 |
|------|------|
| 敏感配置不入代码库 | 微信 AppSecret / JWT 密钥 / 支付通道 key 全部入库 |
| 内存缓存 | `SysConfigService` 读取走内存缓存，不频繁查库 |
| admin 改后刷新 | admin 后台修改 → 调 `refreshCache()` 即刻生效 |
| 首次自动初始化 | `DataInitializer` 在数据库为空时插入默认值 |

```java
@Autowired
private SysConfigService sysConfigService;

String appId = sysConfigService.getValue("wechat.app_id");
int expireHours = sysConfigService.getIntValue("jwt.expire_hours", 168);
boolean mock = sysConfigService.getBoolValue("payment.mock.enabled", false);
```

### 7.4 事件解耦（支付 → 会员）

```
PaymentService.handleProviderPaid(orderId)
    ↓ order.status = PAID
    ↓ applicationEventPublisher.publishEvent(new PaymentSucceededEvent(orderId, uid, planSnapshot))

[Spring 在事务 AFTER_COMMIT 之后]
    ↓
MembershipService @TransactionalEventListener(phase=AFTER_COMMIT)
    ↓ upsertUserMembership(uid, planSnapshot)
    ↓ expireAt = max(now, prevExpireAt) + planSnapshot.durationDays
```

- 事件 DTO 放 `fitcoach-common`，避免 payment ↔ membership 循环依赖；
- AFTER_COMMIT：订单事务必须先成功落库，再激活会员；事务回滚则会员不变；
- PlanSnapshot：套餐在售卖期被改价不影响已下单订单。

### 7.5 支付通道 SPI

```
PaymentChannelProvider 接口
    ├─ String channelCode()                                  通道码（mock / wechat / apple）
    ├─ CreateOrderResult createPay(CreateOrderRequest req)    返回 payParams + immediatelyPaid
    └─ boolean verifyNotify(...)                              通道异步回调验签

实现：
    ├─ MockPaymentProvider          payment.mock.enabled=true 时启用，直接 immediatelyPaid=true
    ├─ WeChatPaymentProvider        微信 V3（WeChatCallbackHandler + WeChatPayV3Helper）
    └─ AppleIAPProvider             Apple receipt 校验（占位，sandbox/prod 切换待补）

PaymentChannelRouter 根据 channel 字段路由到对应 provider；
PaymentService 不感知具体通道，只调 provider 抽象方法。
```

### 9.2 启动

```bash
git clone git@github.com:RicherLan/FitCoachServer.git
cd FitCoachServer

# 一键启动（Docker MySQL + Spring Boot）
bash shell/dev-start.sh

# 或分步：
cd shell && docker-compose up -d && cd ..
mvn spring-boot:run -pl fitcoach-app -Dspring-boot.run.profiles=dev
```

## 十、上传 / 静态资源

### 10.1 配置

```yaml
upload:
  base-dir: ${UPLOAD_BASE_DIR:./uploads}
```

落点约定：

| 业务 | 路径 |
|------|------|
| 用户头像 | `${base-dir}/avatar/<uid>/<uuid>.<ext>` |
| 反馈附件 | `${base-dir}/feedback/<uid>/<uuid>.<ext>` |
| 日志 zip | `${base-dir}/logs/<uid>/<filename>.zip` |

### 10.2 URL 返回约定

服务端只返回相对路径（如 `/static/avatar/u1/a.jpg`），不在 server 拼绝对 URL（避免被反代 Host 头伪造）。客户端 / admin 前端用自己的 baseURL 拼。详见 [`AdminUrlService`](../fitcoach-admin/src/main/java/com/lanprojects/fitcoach/admin/service/AdminUrlService.java) 注释。

## 十一、监控与运维

| 项 | 当前实现 | 后续 |
|----|---------|------|
| 日志框架 | logback-spring.xml（按天滚动 + 单文件 50MB 上限） | ELK |
| 业务日志 | service 关键节点 INFO/WARN/ERROR；GlobalExceptionHandler 统一 ERROR + traceId | 接入 Sentry |
| 调度 | `@Scheduled`（**单实例**） | 多实例需上 ShedLock |
| 健康检查 | `GET /api/auth/ping` | Spring Boot Actuator |
| 数据库迁移 | JPA `ddl-auto=update` | Flyway 基线 + 增量 |

## 十二、后续演进

| 方向 | 说明 |
|------|------|
| **iOS 端补齐** | client 已为 platform 留位，server 端 IAP receipt 校验需补真实实现 |
| **Apple IAP 真接入** | `AppleIAPProvider.verifyReceipt` 接 StoreKit 2，sandbox / prod 切换 |
| **微信 V3 完成** | `WeChatPaymentProvider` mock → V3，`payParams` 返小程序拉起参数 |
| **海外通道** | Stripe / GooglePlayBilling 实现 `PaymentChannelProvider` 即可，business 无感 |
| **自动续订** | UserMembership 加 `autoRenewEnabled`；监听通道续订 webhook |
| **Flyway 引入** | 生产首发前出基线 SQL，关闭 JPA auto-ddl |
| **多实例** | scheduler 套 ShedLock；session 改 Redis 集群 |
| **客户端服务端时间校对** | `ServerTimeContribution` 接入 `/api/client/poll` |
| **OSS 对象存储** | `LogStorageService` / `AvatarStorageService` 抽接口，加 OSS 实现，业务无感 |
