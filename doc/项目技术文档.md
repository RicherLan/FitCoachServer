# FitCoach Server — 后端技术文档

## 一、项目概述

FitCoach Server 是 FitCoach AI 健身教练的后端服务，基于 Spring Boot 构建，为 Android 客户端提供用户认证、数据存储等 API 服务。

### 核心功能

- **微信登录**：接收客户端微信授权码，换取 access_token 并获取用户信息，生成 JWT 返回
- **用户管理**：用户注册/查询、登录状态管理
- **系统配置**：微信 AppId/AppSecret 等敏感配置存储在数据库中，可通过后台管理

### 5.4 客户端版本协议（X-Client-* 五件套）

> 实现：[`ClientInfoInterceptor`](fitcoach-common/src/main/java/com/lanprojects/fitcoach/common/client/ClientInfoInterceptor.java) + [`ClientContext`](fitcoach-common/src/main/java/com/lanprojects/fitcoach/common/client/ClientContext.java) + [`ClientVersionInfo`](fitcoach-common/src/main/java/com/lanprojects/fitcoach/common/client/ClientVersionInfo.java)
>
> 注册：[`WebConfig`](fitcoach-app/src/main/java/com/lanprojects/fitcoach/config/WebConfig.java) `/api/**`（排除 `/api/admin/**`）

#### 协议（每个客户端→server 请求都带）

| Header | 类型 | 例 | 用途 |
|---|---|---|---|
| `X-Client-Platform` | string | `android` / `ios` | 区分平台 |
| `X-Client-Native-Version-Code` | int | `1002003` | 安装包版本（应用市场上架的） |
| `X-Client-Native-Version-Name` | string | `"1.2.3"` | 同上，可读 |
| `X-Client-Bundle-Version-Code` | int | `1002005` | 当前运行的 JS bundle 版本（OTA 后会与 native 不同） |
| `X-Client-Bundle-Version-Name` | string | `"1.2.5"` | 同上，可读 |

**编码规则**：`MAJOR*1_000_000 + MINOR*1_000 + PATCH`（每段 0-999）。例 `1.2.3 → 1_002_003`。RN 客户端 / Android Kotlin / iOS ObjC / Server Java 算法严格一致。

**两层版本设计要点**：
- `nativeVersion` ← gradle / Info.plist，改动场景：加 native 依赖、改原生 Module。判断"用户的安装包是否支持某个新 native 接口"。
- `bundleVersion` ← RN `package.json` 的 `version`，改动场景：纯 JS/TS 改动。判断"当前运行的代码是否实现了某个新业务契约"。未来接 OTA 后可静默推送。

#### 业务侧使用

```java
import com.lanprojects.fitcoach.common.client.ClientContext;

// 1) 直接读 versionCode 做条件判断（最常用）
if (ClientContext.bundleVersionCode() >= 1_001_000) {
    // 1.1.0 起支持新接口契约，走新逻辑
}

// 2) 平台分流
if (ClientContext.isIos()) { ... }

// 3) 拿全量信息
ClientVersionInfo info = ClientContext.get();
if (info.isEmpty()) {
    // admin 后台 / Postman / 老版本无埋点客户端
}
```

#### 缺失语义

- admin 后台、Postman 调试请求 → `ClientContext.get()` 返回 `EMPTY`，业务自己判 `isEmpty()` 即可。
- Header 存在但格式异常（如 versionCode 不是数字）→ 静默降级为 0，不打 ERROR 日志。

## 七、配置管理设计

本项目采用**数据库存储动态配置**的方案，避免敏感信息硬编码。

### 设计原则

1. **敏感配置不入代码库**：微信 AppSecret、JWT 密钥等存在数据库中
2. **支持热更新**：管理员通过后台修改后调用 `SysConfigService.refreshCache()` 即刻生效
3. **内存缓存**：配置读取走内存缓存，不频繁查库
4. **首次启动自动初始化**：`DataInitializer` 在数据库为空时自动插入默认配置

### 读取配置示例

```java
// 在 Service 中注入 SysConfigService
@Autowired
private SysConfigService sysConfigService;

// 读取字符串配置
String appId = sysConfigService.getValue("wechat.app_id");

// 读取整数配置（带默认值）
int expireHours = sysConfigService.getIntValue("jwt.expire_hours", 168);
```
