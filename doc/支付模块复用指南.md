# Payment 模块复用接入指南

> 本文档说明如何把 FitCoach 的支付/退款子系统（`fitcoach-payment` + `fitcoach-common` 中的支付事件）
> **原样搬到任意新 App** 复用。经过「去业务化重构（波 0）」后，payment 模块不认识任何业务概念
> （会员/金币/课程），只处理「某用户为某商品付了多少钱、走什么渠道、成没成功、退没退」。

---

## 1. 设计理念:payment 是「支付内核」,业务是「插件」

```
┌─ 业务层（每个 App 不同，你要写的部分）──────────────┐
│  membership / coins / course ...                    │
│    ├ 查商品、算价 → 构造 ProductSnapshot 调下单       │
│    └ 监听 PaymentSucceededEvent / PaymentRefundedEvent│
│       按 productType 认领 → 发货 / 退货               │
└──────────────────────────────────────────────────────┘
        ↓ 仅通过「事件 + ProductSnapshot 契约」耦合
┌─ payment 复用内核（搬到任何 App 一行不改）┈┈┈┈┈┈┈┈┈┐
│  PaymentService        下单/查单/关单/markPaid        │
│  RefundService         退款（ACTIVE/PASSIVE 两模式）  │
│  PaymentChannelRouter  渠道路由 + flavor×platform 白名单│
│  Provider SPI          WeChat / AppleIAP / GooglePlay │
│  超时关单 / 会员激活补偿 / 生产安全守卫 Jobs           │
│  自带 sys_config keys（换 App 只改配置值）            │
└┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┘
```

**关键原则**:payment 模块**绝不 import 任何业务模块**;业务模块通过 Spring 事件被动接收支付结果。

## 2. 复用单元清单(要拷贝的文件)

| 复用单元 | 位置 |
|---|---|
| 支付核心 | [`fitcoach-payment`](../fitcoach-payment) 整个模块 |

## 3. 核心契约(business ↔ payment 的唯一接口)

### 3.1 下单契约 `ProductSnapshot`

[`ProductSnapshot`](../fitcoach-payment/src/main/java/com/lanprojects/fitcoach/payment/service/ProductSnapshot.java):

```java
public record ProductSnapshot(
    String productType,   // 业务自定义，如 "MEMBERSHIP" / "COINS"（payment 只透传，不解释）
    String productCode,   // 商品业务 code，如会员套餐 "MONTHLY"
    String productName,   // 展示名快照（防改名后历史订单错乱）
    Integer priceCny,     // 国内价格（分）
    Integer priceUsdCents // 海外价格（美分），IAP/GooglePlay 通道必填
) {}
```

### 3.2 支付成功事件 `PaymentSucceededEvent`

payment 在订单转 PAID 后（`AFTER_COMMIT`）发布,业务方监听并**按 productType 认领**:

```java
@Async
@TransactionalEventListener(phase = AFTER_COMMIT, classes = PaymentSucceededEvent.class)
public void onPaymentSucceeded(PaymentSucceededEvent event) {
    if (!MyProductType.COINS.equals(event.getProductType())) return; // 只认领自己的
    coinsService.grant(event.getUserId(), event.getProductCode(), event.getOrderId());
}
```

### 3.3 退款成功事件 `PaymentRefundedEvent`

对称设计,业务方按 productType 认领后撤/扣权益(`fullyRefunded` 区分全额/部分):

```java
@Async
@TransactionalEventListener(phase = AFTER_COMMIT, classes = PaymentRefundedEvent.class)
public void onPaymentRefunded(PaymentRefundedEvent event) {
    if (!MyProductType.COINS.equals(event.getProductType())) return;
    if (event.isFullyRefunded()) coinsService.revoke(event.getUserId(), event.getProductCode());
}
```

## 4. 新 App 接入 4 步

**参考实现**:会员业务就是一个「插件」,可直接照抄——
[`MembershipProductType`](../fitcoach-membership/src/main/java/com/lanprojects/fitcoach/membership/MembershipProductType.java)、
[`MembershipService`](../fitcoach-membership/src/main/java/com/lanprojects/fitcoach/membership/service/MembershipService.java) 的 `onPaymentSucceeded` / `onPaymentRefunded`。

1. **引依赖**:新 App 的 composition root 引入 `fitcoach-payment` + `fitcoach-common`。
2. **定义 productType 常量**:如 `public static final String COINS = "COINS";`（payment 不认识，你自己约定）。
3. **下单**:在你的 Controller 查商品 → 构造 `ProductSnapshot(COINS, ...)` → 调
   [`PaymentService.createOrder`](../fitcoach-payment/src/main/java/com/lanprojects/fitcoach/payment/service/PaymentService.java)（参考 [`PaymentController`](../fitcoach-app/src/main/java/com/lanprojects/fitcoach/controller/payment/PaymentController.java)）。
4. **发货 / 退货**:写两个 `@TransactionalEventListener` 监听上面两个事件,按 productType 认领。

**就这样。** payment 模块、退款子系统、渠道路由、回调、对账 job 全部零改动。

## 5. 支付渠道 & 退款模式

| 渠道 | 支付模型 | 退款模式 | 实现 |
|---|---|---|---|
| 微信 WECHAT | 服务端统一下单 → 客户端拉起 | **ACTIVE** 调 API 原路退 | [`WeChatPaymentProvider`](../fitcoach-payment/src/main/java/com/lanprojects/fitcoach/payment/provider/wechat/WeChatPaymentProvider.java) 完整 |
| Apple IAP | 客户端发起 → 服务端验单 | **PASSIVE** ASSN 通知退 | [`AppleIapService`](../fitcoach-payment/src/main/java/com/lanprojects/fitcoach/payment/provider/apple/AppleIapService.java) 骨架 |
| Google Play | 客户端发起 → 服务端验单 | ACTIVE + RTDN 通知 | [`GooglePlayService`](../fitcoach-payment/src/main/java/com/lanprojects/fitcoach/payment/provider/google/GooglePlayService.java) 骨架 |

**退款两种模式**（[`RefundMode`](../fitcoach-payment/src/main/java/com/lanprojects/fitcoach/payment/entity/RefundMode.java)）:
- `ACTIVE`:商户调通道 API 退款 → `RefundService.refund`（按 Provider `supportsActiveRefund()` 自动选）
- `PASSIVE`:平台已退款的通知场景（Apple ASSN / Google RTDN）→ `RefundService.recordPassiveRefund`（强制记账,不再调 API）

## 6. 新增一个支付渠道(如支付宝)

1. 在 [`PaymentChannel`](../fitcoach-payment/src/main/java/com/lanprojects/fitcoach/payment/entity/PaymentChannel.java) 加枚举值（如已有 `ALIPAY` 预留）;
2. 新建 `AlipayProvider implements PaymentChannelProvider`,实现 `channel()` / `isAvailable()` / `createOrder()`;
   支持主动退款则覆写 `supportsActiveRefund()` + `refund()`;
3. `PaymentChannelRouter` 会**自动发现**（它注入 `List<PaymentChannelProvider>`），无需手动注册;
4. 在 `PaymentChannelRouter.FLAVOR_PLATFORM_WHITELIST` 把该通道加入对应 flavor×platform;
5. RN 端 `flavorProfile.paymentChannels` 加入该通道值。

**PaymentService / Controller / RefundService 均不需改动。**

| 全局 | `payment.mock.enabled`（生产必须 false,[`PaymentProductionGuard`](../fitcoach-payment/src/main/java/com/lanprojects/fitcoach/payment/PaymentProductionGuard.java) 会 fail-fast） |

| Apple | `payment.apple.{enabled,bundleId,sharedSecret,sandbox}` |
| Google | `payment.googleplay.{enabled,packageName,serviceAccountJson}` |

## 9. 上线前检查清单

### 2026-09-22 验签更新

Apple 使用 [官方 Java 库 5.2.0](https://github.com/apple/app-store-server-library-java) 验证 JWS 和证书链，开启在线证书检查；不再支持仅解码凭证。配置 `payment.apple.rootCertificatesPem`（从 Apple PKI 获取的根证书 PEM，可串接多个）、`payment.apple.bundleId`、`payment.apple.appAppleId`（生产必填）、`payment.apple.sandbox`，并按套餐配置 `payment.apple.productId.<productCode>`。配置缺失拒绝下单/验单。旧 sharedSecret 不用于 StoreKit 2 验签。

下单响应新增 `payParams.productId` 与 `payParams.appAccountToken`，客户端 StoreKit 购买必须原样携带 appAccountToken；服务端校验当前用户、订单通道、商品快照、交易号、撤销状态及该 token。旧订单没有商品快照时不能自动验单，需重新下单。Apple 通知外层和内层均验签，处理失败返回 HTTP 503 供平台重试。Google 支付按用户要求暂不修改，仍是未完成的骨架。

- [ ] 微信 6 项配置 + 平台证书就位,`notifyUrl`/`refundNotifyUrl` 为 https 且已在微信商户后台登记
- [ ] Apple:补全 [`AppleIapService`](../fitcoach-payment/src/main/java/com/lanprojects/fitcoach/payment/provider/apple/AppleIapService.java) 的 **JWS 证书链验签**（当前骨架未验签,生产必做）;ASSN V2 回调 URL 登记到 App Store Connect
