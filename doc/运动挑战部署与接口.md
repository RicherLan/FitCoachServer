# 运动挑战：部署与接口

首版项目 `pushup`，规则 `pushup-60-v1`，固定 MediaPipe 3D；12 关、3 档难度、60 秒竞技。识别仍在手机端，服务端接收最小计数事件摘要，不接收视频。本功能不涉及支付。

## 部署

已有云服务器执行：

```bash
cd /opt/fitcoach/FitCoachServer && bash shell/update.sh
```

更新脚本先拉代码、备份，再执行迁移清单中的 `20261014_challenge.sql`，新增 `challenge_session` 和 `challenge_audit`；不删除已有表。已执行迁移不会重跑。不要仅用旧 `deploy.sh` 绕过本次数据库迁移。

本地开发数据库首次接入也要执行 `fitcoach-app/src/main/resources/sql/20261014_challenge.sql`；挑战表使用 JDBC 管理，不依赖 Hibernate 自动建表。使用本人本地 MySQL 连接参数导入这份 SQL，不使用生产凭据。

首次初始化默认开启：Server 为缺失的 `challenge.enabled`、`challenge.pushup.enabled` 创建值为 `true` 且启用的配置。Admin 系统配置中筛选 `challenge`，将任意一项配置值设为 `false` 即可关闭；恢复时两项都需为 `true`，并保持两条配置项“启用”。配置写入 MySQL，重启/更新 Server 不会覆盖。关闭开关禁止新开局，历史及合法已开局结算继续可用。

升级说明（2026-10-15）：旧版已生成的 `false` 配置仍保留，不自动覆盖；如需开启，在 Admin 将这两项配置值改为 `true` 一次即可。配置项被禁用或读取失败时仍禁止新开局，不能绕过后台关闭设置。

## 客户端接口

统一 `Result<T>` 包装；需要登录的接口使用现有用户 Bearer token，内部 user_id 取认证上下文。

| 接口 | 用途 |
|---|---|
| GET `/api/challenges/catalog` | 开关、项目、规则、模型、关卡基础组目标 |
| GET `/api/challenges/me` | 本人进度、XP/等级/徽章、周排名、历史最佳、最近100场；不返回榜外总排名 |
| POST `/api/challenges/sessions` | 创建；project/ruleVersion/model/mode/level/difficulty/publicScore |
| POST `/api/challenges/sessions/{id}/finish` | 幂等结算；events相对开赛毫秒数组、sets每组次数、elapsedMs、completed、interrupted |
| POST `/api/challenges/sessions/{id}/withdraw` | 撤回本场公开资格，不可重新公开，不删除训练日志 |
| GET `/api/challenges/board?period=week` | 当前北京时间周榜前100人 |
| GET `/api/challenges/board?period=all` | 当前规则总榜最多30人，无榜外分页/排名接口 |

完整正常竞技需要 elapsedMs=60000，服务端开赛后60秒至10分钟内提交。事件终点为开区间，间隔小于400ms等明显异常进入 REVIEW。中断/超时/零次为 PRACTICE。闯关目标和解锁由服务器重验；最长一小时。此验证不等于防篡改硬件认证，首版不用于现金或实物奖励。

同一用户开始与结算通过用户行锁串行化，同场结算后重复请求返回原结果，不重复发经验/写日志。正次数场次在同一事务创建一条 training_record，clientId=`challenge-场次ID`，备注标记闯关/竞技及场次。零次数只保留挑战历史，不创建不符合原日志“至少一次”约束的空训练。编辑普通日志不会反向改比赛成绩。

每人取最佳，按分数竞赛排名（1、1、3），同分按最早开赛时间及场次ID稳定排序；总榜LIMIT30不因并列扩容。周属以服务端开赛时间、北京时间周一划分。用户禁用或删除时通过用户有效性JOIN即时移出公开榜。

成长从 CONFIRMED 场次重新计算：每日动作经验最多100，每关跨难度首通20，每100经验升级。复核/撤销立即影响排名和经验，无额外奖励流水重复发放。

## 受控复核（不建设 Admin 游戏编辑器）

`POST /api/admin/challenges/{id}/review` 使用现有 Admin token，VIEWER 禁写；请求 `{ "state": "REVOKED", "reason": "填写核查原因" }`。state允许 CONFIRMED/REVIEW/REVOKED，不能修改次数，不能把 ACTIVE/PRACTICE 提升为公开有效成绩。操作在 `challenge_audit` 记录操作者、原因、前后状态、时间。未经核查不要把 REVIEW 改为 CONFIRMED。

客户端“问题反馈”复用原渠道；历史/结算页提供可复制场次ID。检查 `challenge_session.payload` 可见事件摘要和版本/设备上下文，仅限有权限的运维人员，不对公众返回。

## 验证与发布前检查

- JUnit 覆盖周界、目标、时间边界、重复提交、越权、超时/中断、异常速度、禁止提升练习。
- shell/tests/test_update.py 覆盖迁移顺序、跳过已执行、失败停止等编排；它不连接真实 MySQL。
- 本机尚无可用 MySQL/Docker 实例，真实 MySQL 8 窗口排名 SQL、迁移及双端端到端需部署测试环境后验收。不要将单元测试描述为真实数据库集成测试。
- 启用前按 RN 产品文档验收跨周、35人总榜仅30人、同分、撤回、复核、后台中断、断网补交。服务器更新完但客户端未装新包时，旧客户端不会出现挑战入口。
